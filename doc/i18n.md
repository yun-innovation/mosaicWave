# i18n and l10n

Milestone 3 design. The web UI and user-facing server errors can be shown in English, Traditional Chinese, and Simplified Chinese. Agent rule: [`.cursor/rules/i18n.mdc`](../.cursor/rules/i18n.mdc).

## Locales

| Locale | Language | Browser tags that select it |
| --- | --- | --- |
| `en` | English (default, source text) | everything not listed below |
| `zh-Hant` | Traditional Chinese | `zh-HK`, `zh-TW`, `zh-MO`, `zh-Hant*` |
| `zh-Hans` | Simplified Chinese | `zh-CN`, `zh-SG`, `zh`, `zh-Hans*` |

A missing key falls back to `en`.

## Web UI

- Library: `i18next` + `react-i18next`. Resources are bundled into the static export (imported JSON, no HTTP backend), because the UI is a single static page served by FastAPI.
- Files: `src/web/app/locales/{locale}/{namespace}.json`. Namespaces follow screens: `common`, `auth`, `gallery`, `import`, `settings`, `errors`.
- Keys: `namespace:area.item` in camelCase (e.g. `settings:saveFolder.button`). English JSON is the source of truth.
- Interpolation `{{name}}`; plurals with i18next suffixes (`_one`, `_other`), which use `Intl.PluralRules`.
- Type safety: TypeScript `CustomTypeOptions` typed from the English resources, so a wrong key fails `next build`.
- Completeness: `scripts/i18n-check` runs before `npm run build` and fails when `zh-Hant` or `zh-Hans` has a missing or extra key compared to `en`.
- Formatting: dates, numbers, and byte sizes use `Intl.DateTimeFormat` / `Intl.NumberFormat` / `Intl.RelativeTimeFormat` with the active locale. Do not pass `undefined` as the locale.
- `document.documentElement.lang` follows the active locale (the static export renders `lang="en"`).

## Choosing the locale

1. Signed-in user's saved choice (`user.locale`).
2. Last locale used in this browser (`localStorage`), for the sign-in screen before anyone is signed in.
3. `navigator.languages`, mapped with the table above.
4. `en`.

Settings has a language menu: Automatic (follow the browser), English, 繁體中文, 简体中文. Changing it switches the UI at once, saves to the server, and updates `localStorage`.

## Server

- `user.locale` TEXT NULL — a locale from the table above, or NULL for automatic ([schema.md](schema.md)).
- `GET /api/v1/me` and `GET /api/v1/auth/status` return `locale`. `PATCH /api/v1/me` with `{"locale": "zh-Hant" | "zh-Hans" | "en" | null}` sets it ([architecture.md](architecture.md)).
- Errors the UI may show carry a stable `code` and optional `params` next to the English `detail`:

```json
{ "detail": "asset not found", "code": "asset_not_found", "params": {} }
```

  The UI translates `errors:{code}` and falls back to `detail`. `detail` stays, so `/api/v1` remains compatible. Codes are `snake_case`. Takeout import warnings already carry `code` and use the same lookup.
- Migration order for the ~72 existing `detail` strings: auth and setup, Takeout import, Settings / Save folder, then the rest.

## Not translated

- User data: album names, filenames, folder paths, Takeout album titles
- Server logs, `mosaicWave.log`, command-line output (`wipe`, `port-who`, `mosaicWave.sh`)
- OpenAPI docs and JSON field names
- Installers (MSI wizard, QPKG App Center text, `install.sh`) — later item
- Right-to-left layout

## Done when (milestone 3)

- Every user-facing string in `src/web/app` goes through `t()`
- `zh-Hant` and `zh-Hans` are complete and `i18n-check` passes
- `user.locale` is saved and follows the user across devices
- Auth, Takeout, and Settings errors show in the chosen language
