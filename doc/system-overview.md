# System overview

## Purpose

mosaicWave is a personal photo and video library that **runs on QNAP, Windows, or Linux**. It should feel closer to Google Photos (timeline, browse, backup-from-phone later) than to a generic file browser, while **keeping the media as ordinary files** when the storage backend is a local folder (including QNAP shared folders).

The **Python service** is the system of record. The web UI and future mobile apps are clients of one API. QNAP QPKG is a first-class install shape, not the only one.

## Who it is for

- A household or small team that stores photos on a QNAP, a PC, or a Linux box.
- Users who want a gallery **without sending the library to Google**.
- Users who still want File Station, SMB, or Explorer to see the **same files** when sources are local folders.

It is not a public social network, not a SaaS, and not a Docker-only appliance as the primary product.

## Problem we are solving

QuMagie is the official QNAP gallery. Self-hosted clones (Immich, PhotoPrism) usually mean **Docker**. mosaicWave is a **single Python service** plus a static web UI and an HTTPS API: install as a **native QPKG** on QNAP, or run **standalone** on Windows/Linux.

Gaps we care about (vs “just use a file browser”):

- Timeline and gallery, not only folder trees
- Thumbnails and metadata (EXIF dates, later albums)
- A stable API so web and mobile stay in sync
- Indexer that watches folders the user chooses
- The same app on more than one kind of host, via a [virtual file/blob module](storage.md)

Gaps we will **not** try to close in v1:

- Live Google Photos Library API / Picker as a full-library importer
- Matching QuMagie AI people/places on day one
- Running Node.js or a second app server as the product runtime

## Capabilities

### In scope (product)

| Area | Intent |
| --- | --- |
| Library | One private library per user (`{data_dir}/libraries/{user_id}`) |
| Index | Scan files via FileStore, extract EXIF/basic video metadata, store in a local DB |
| Gallery | Chronological timeline, folder browse, photo/video detail |
| Thumbs | Generated by Python; stored in BlobStore |
| Access | Web UI served by FastAPI from the Next.js export |
| Clients | Same REST/OpenAPI for web and mobile |
| Coexistence | Originals remain readable outside mosaicWave **when FileStore is local disk** |
| Hosts | QNAP QPKG and standalone Windows/Linux |

### Out of scope (for now)

- Live Google Photos Library API / Picker as a full-library importer
- Replacing Qfile Pro or Explorer as a general file manager
- Transcoding farm / Plex-style streaming product
- Multi-tenant cloud hosting
- FUSE/WinFsp mounts of the library

Google **Takeout** import (extracted folders + JSON sidecars) is a **Phase 2** feature so we can **seed SQLite** with a sample library on Windows. Live Photos APIs are not used. Details: [takeout.md](takeout.md).

## Runtime principles

1. **One process on the host:** Python (uvicorn/FastAPI). QPKG start/stop is shell; standalone is the same process with a data dir.
2. **UI is files:** `next build` with `output: 'export'` on a developer machine; the host only serves the built assets plus `/api`.
3. **API first:** Any UI feature that needs data goes through the HTTP API so mobile can follow.
4. **Files stay files** on FileStore. On Windows, MSI uses `%PROGRAMDATA%\mosaicWave`; local debug uses `%PROGRAMDATA%\mosaicWave-dev`. Admin Settings can move that folder. Takeout is a **one-shot ingest** into the caller’s private library; then the dump can be deleted.
5. **Host-friendly:** Prefer modest RAM; no Node; no Docker requirement. QPKG remains native.
6. **Storage is virtual:** originals and thumbs go through FileStore/BlobStore ([storage.md](storage.md)).

## Relationship to other QNAP software

| Product | Relationship |
| --- | --- |
| File Station / SMB | Same files when sources are local shares; mosaicWave indexes, does not hide them |
| QuMagie | Competitor/adjacent; we do not depend on its database |
| Qfile Pro | Can upload into the same folders; duplicate auto-backup is a user choice, not something we solve in v1 |
| Container Station / Immich | Alternative architecture we are **not** shipping as the app |

On Windows/Linux, Explorer or the desktop file manager plays the same coexistence role as File Station.

## Success for the first usable release

A user installs the QPKG **or** runs standalone, points at a folder of photos, and in the web UI sees a **timeline of thumbnails** that open the original (or a preview). Identity is **QNAP users on QTS** or **local users on standalone**; **authorization** is per-source grants (members do not see everything). A mosaicWave API session follows. Must exist before the API is exposed beyond localhost.
